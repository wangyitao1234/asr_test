# 测量口径

## 负载和计时

音频读取、解码、单声道16k校验和哈希在正式计时外完成。固定seed打乱清单，先分出独立预热集，再取正式输入；预热数不同就会导致正式集合不同。所有正式音频默认解码PCM唯一，不允许仅换文件名掩盖重复。

正式计时包括上传、连接池等待、服务排队、推理、完整响应接收及客户端记录开销，不包括服务启动、模型编译、语料准备、预热和CER计算。吞吐为成功请求数/整轮正式墙钟时间；音频秒/墙钟秒不是业务可持续并发数。

最多启动concurrency个worker，一个请求完成后补下一个；有限请求尾部会自然降并发。要分析性能下降，应结合客户端实际在途数、失败/超时、请求时刻、音频时长与输出长度、服务监控，而不能只看瞬时并发。

## CER和精度

CER为所有有参考文本的成功请求的字符编辑距离之和/参考字符数之和。归一化采用NFKC、小写、去除Unicode标点/符号/空白，不做简繁、数字转换。CER只覆盖成功请求，因此必须同时报告失败和成功率。

相同CER不等于逐条文本相同。A/B脚本会核对输入并统计文本差异。参考文本缺失时不得宣称精度不退化。拼接长语料的源句可能共享，按整文件bootstrap不能代表独立自然业务总体。

## 缓存证据

vLLM后端检查显式配置及prefix/MM计数器增量；缺少计数器、计数器重置、缓存配置不符会使严格结果无效。计数器必须来自专用服务，其他请求会污染增量。`disabled`、`prefix-only`、`observe`是不同实验，不能混用结论。

FunASR后端校验独立PCM和预热隔离，但不暴露命中计数器，因此缓存验证记为null；部署方还需检查真实后端是否做结果缓存。GPU分配器、编译Graph、权重、OS页缓存不等于复用音频或识别结果，也不应每请求冷启动模型来模拟“无缓存”。

## 公平比较

固定机器、设备、语料、seed、预热数、请求数、并发、请求参数、服务版本和精度。A与B串行运行，避免GPU或CPU负载重叠；推荐AB/BA复测。先比较成功率、完整文本和CER，再比较性能。不能将小算子TFLOPS、带profiler的耗时或模型加载时间与正式HTTP耗时混为一谈。
